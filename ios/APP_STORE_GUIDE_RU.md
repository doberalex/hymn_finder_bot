# Путь первого релиза «Гимны» в App Store

## 1. Что уже готово

- нативное приложение для iPhone и iPad на SwiftUI;
- офлайн-каталог из 16 542 гимнов;
- поиск, сборники, избранное, настройка текста и отправка;
- иконка бота и Bundle ID `ru.doberalex.hymnfinder`;
- версия MVP `0.1.0`, build `1`.

## 2. Что необходимо решить до публикации

1. **Права на контент.** Для каждого песенника зафиксировать источник, автора/издателя, статус public domain или письменное разрешение. Наличие текста в файлах бота само по себе не означает право распространять его через App Store.
2. **Имя продавца.** При регистрации как физическое лицо в App Store показывается юридическое имя владельца аккаунта. Для отображения названия организации нужен аккаунт организации и D‑U‑N‑S.
3. **Название приложения.** Проверить доступность имени в App Store Connect. Рабочее имя сейчас — «Гимны».
4. **Сайт.** Нужны публичные HTTPS-страницы поддержки и политики конфиденциальности. Даже офлайн-приложению лучше иметь короткую политику, явно сообщающую, что данные не собираются.

Подготовленные материалы находятся в каталоге [`AppStore`](AppStore/README.md), а исходники сайта — в `support-site` в корне репозитория.

## 3. Запуск на своём iPhone

1. Открыть `HymnFinder/HymnFinder.xcodeproj` в Xcode.
2. Подключить iPhone кабелем, разблокировать и подтвердить доверие компьютеру.
3. В Xcode открыть **HymnFinder → Signing & Capabilities** и выбрать свой Team.
4. Если Xcode сообщает, что идентификатор занят, заменить Bundle Identifier на уникальный, например `ru.<ваш-домен>.hymns`.
5. Выбрать iPhone в верхней панели и нажать ▶︎.

Для разработки и запуска на личном устройстве платная подписка не обязательна. Для TestFlight и App Store нужна Apple Developer Program.

## 4. Минимальная проверка перед TestFlight

- поиск по номеру в общей базе и внутри конкретного сборника;
- поиск по фрагментам на русском, украинском, английском и узбекском;
- открытие длинных гимнов, изменение размера шрифта, копирование и отправка;
- добавление/удаление избранного и сохранение после перезапуска;
- светлая и тёмная темы, крупный системный шрифт, VoiceOver;
- iPhone SE/mini и большой iPhone; iPad — если оставляем его в поддерживаемых устройствах;
- авиарежим и первый запуск без сети;
- отсутствие дублей и явно повреждённых текстов.

## 5. TestFlight и публикация

1. Зарегистрироваться в Apple Developer Program.
2. Создать приложение в App Store Connect с тем же Bundle ID.
3. В Xcode установить маркетинговую версию `1.0.0`, build `1`, затем **Product → Archive**.
4. В Organizer выбрать **Distribute App → App Store Connect → Upload**.
5. После обработки сборки добавить внутренних тестировщиков TestFlight. Для внешних тестировщиков потребуется beta review.
6. Подготовить название, подзаголовок, описание, ключевые слова, категорию, возрастной рейтинг, copyright, URL поддержки, URL политики, скриншоты и ответы App Privacy.
7. Выбрать сборку, заполнить App Review Information и отправить на review.
8. Для первого релиза выбрать ручной выпуск: после одобрения приложение не появится в магазине, пока владелец не нажмёт Release.

## 6. Как выпускать обновления

Каждое обновление имеет две независимые величины:

- **Version** — видимая пользователю версия, например `1.0.1`;
- **Build** — уникальный номер загруженной сборки, например `2`, `3`, `4`.

Цикл обновления: создать ветку → внести изменение → обновить/добавить тест → проверить на устройстве → увеличить версию/build → TestFlight → резерв 2–5 дней на обратную связь → отправить review → включить phased release для осторожного семидневного развёртывания.

Для обновления каталога выполнить из корня репозитория:

```bash
python3 scripts/build_ios_catalog.py
```

После релиза раз в неделю проверять crash-отчёты, отзывы и обращения; раз в месяц — актуальность Xcode/iOS и контента; перед каждым релизом — текущие App Review Guidelines и требования к загрузке.
